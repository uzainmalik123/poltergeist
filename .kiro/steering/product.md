# Product

**Poltergeist** reads a Kiro spec, turns each acceptance criterion into adversarial "ghost users" that test the real running app, and writes a haunting report into the spec folder so Kiro's agent can fix what's broken and re-check it.

- **Who it's for:** developers who build with Kiro specs.
- **What it's for:** proving the shipped app keeps the promises in `requirements.md`.
- **What it is not:** a security scanner, a load tester, or an LLM driving a browser live.
- **The look:** a haunted terminal. Everything visual is ASCII glyphs, and only ghosts glow (`docs/THEME.md`).
- **The hackathon:** Kiroween 2026, Costume Contest category (D-23). Kiro is integrated into the product itself (MCP, hook, steering, Power), not just used to write it (D-01).

The spec is in `.kiro/specs/poltergeist/`. Scope and priorities are in `docs/PRD.md`.
