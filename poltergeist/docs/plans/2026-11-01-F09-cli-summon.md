# F09 CLI `summon` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `poltergeist summon --spec <dir>` runs the whole haunting (config → spec → scout → compile → run → verdicts → report), prints a themed board, and exits 0, 1, 2 or 130.

**Architecture:** the orchestration is `summon(opts)` in `packages/core/src/summon/`, with the LLM, browser launcher and event listener injected, so F11 (MCP) and F12 (Séance) can reuse it (design §1). A new `packages/cli` (`@poltergeist/cli`, bin `poltergeist`) is a thin front door: it parses flags, draws terminal output, maps results and errors to exit codes, and (with `--seance`) runs a loopback WebSocket event server. Built fixture-first on the claims fixture with a fake LLM (D-36). The real Candy Swap run is KI-42.

**Tech Stack:** TypeScript (Node ≥ 22, ESM), `node:util` `parseArgs`, playwright-core, `ws` 8.22.0, tsx 4.23.15 (runs the bin; no build step), vitest.

**Spec:** `.kiro/specs/poltergeist/requirements.md` Requirement 9.1–9.2 · `docs/PRD.md` § F09 · `docs/DECISIONS.md` D-36 (plus D-17, D-33, D-34, D-35) · `docs/THEME.md` §2, §4, §5 (CLI) · design §8–§9.

## Global Constraints

- Exit codes (Req 9.2, D-36): `0` nothing haunted · `1` any criterion haunted · `2` usage/config/system error · `130` Ctrl-C.
- `NO_COLOR` (any non-empty value) or a non-TTY stdout means no colour and no animation (THEME §5).
- The `:6660` event server starts only with `--seance`, bound to `127.0.0.1`, path `/runs/<runId>` (PRD F09, design §8).
- `ConfigError` and `ResetError` map to exit 2 (PRD F09). A reset failure on **every** rep counts as `ResetError` (D-36).
- Launch Chromium only with `guardLaunchOptions()` (D-18, D-22). Never edit the user's `requirements.md`, `design.md` or `tasks.md` (D-14).
- Ectoplasm (`#7dffb0`) colours ghosts only. Verdict colours: haunted `#ff3b5c`, flaky `#ffb020`, inconclusive/uncompilable `#8b93a7`, clean `#d6d9cc`, notApplicable/notRun `#69707a` (THEME §2, §4).
- Plain QA wording only in anything that reaches a prompt (D-09). Theme words in terminal output are fine.
- Pinned exact versions. `ws` `8.22.0`, `tsx` `4.23.15`. No new dependencies beyond those.
- Keep invisible and bidi characters as `\uXXXX` escapes in source (AGENTS).
- Run `npm run health` at the end of every task. Commit messages are `F09: <what>`.

## Review Focus

1. **A run where nothing could execute** (every reset fails, so every pair is inconclusive): the user expects exit 2 with the reset error shown, not a green 0. Test in Task 3 (summon reports `allResetsFailed`) and Task 7 (exit 2).
2. **Typos in `--only` / `--personas`** (`--only 9.9`, `--personas ghost`): the user expects exit 2 naming the bad id before any browser or LLM work. Test in Task 3.
3. **Hostile criterion text** (`<!--`, `[x](http://…)`, `‮`): the user expects the report and the board not to hide or reorder content. Test in Task 1 (report) and Task 5 (board strips control/bidi characters).
4. **Port 6660 already taken with `--seance`**: the user expects an immediate exit 2 naming the port, before scouting. Test in Task 6 and Task 7.
5. **Ctrl-C mid-run**: the user expects the browser closed, no half-written report, exit 130. Test in Task 7 (abort via the injected signal).

Order inside `summon` (each step's failure propagates its own error class):
1. `specDir = resolve(cwd, opts.specDir)`; `loaded = await loadConfig({ path: configPath, cwd, env })`; pass every `loaded.warnings[i].message` to `onWarning`.
2. `parseSpec(specDir)`. Select `only` ids (unknown id → `UsageError('unknown criterion id: 9.9 (known: 3.1, 3.2)')`). Zero selected criteria → `UsageError('no acceptance criteria to haunt in <specDir>/requirements.md')`.
3. Personas: dedupe while keeping order; any id failing `isPersonaId` → `UsageError('unknown persona: ghost (known: wraith, banshee, doppelganger)')`. Default `PERSONA_IDS`.
4. `reps` outside 1–10 → `UsageError`. `runDir = join(loaded.configDir, '.poltergeist', 'runs', runId)`; `cacheDir = join(loaded.configDir, '.poltergeist', 'cache', 'plans')`.
5. Create the sink with `outDir: runDir`. Emit `run.started`. Write `run.json` = `{ runId, specDir, specHash (sha256 hex of requirements.md), config: loaded.snapshot, model, options: { only, personas, reps, recompile }, startedAt }`.
6. `browser = await launch()`. In a `try/finally` that always closes it: `scout(browser, loaded, { outDir: runDir, onRoute: emit scout.route })`, then `compile(criteria, scoutResult, { client: llm, model: loaded.config.model, cacheDir, outDir: runDir, personas, recompile, onWarning, onPlan: emit plan.compiled })`. If `loaded.config.concurrency === 1` and any compiled plan has `actors.b`, warn `concurrency 1: two-actor plans still open 2 contexts` (KI-37). Then `runPlans(browser, loaded, plans, { sessions, outDir: runDir, reps, signal, onEvent, ...runOptions })`.
7. Check `opts.signal?.throwIfAborted()` between stages. On abort, write no report.
8. `verdicts = computeVerdicts(compiled.pairs, run)`; emit `verdict.pair` for each pair and `verdict.criterion` for each criterion; write `verdicts.json`.
9. `renderReport` with `run: { runId, runDir, target, reps: run.reps, model, startedAt }`, then `writeReport(specDir, …)`. `allResetsFailed = run.resets.length > 0 && run.resets.every(r => r === null)`. Read `resetError` from the first `reset.finished` event with `ok: false` that you saw.
10. Update `run.json` with `finishedAt`, `durationMs`, `scoutHash`, `counts`. Emit `run.finished`, then `await sink.flush()`.
