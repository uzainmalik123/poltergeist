# F12 Live Feed (headless) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn F12 into the engine's headless live feed: a pure, render-agnostic `LiveState` that Reanimator's R4 attack scene folds run events into, served over a hardened `--seance` WebSocket.

**Architecture:** A new pure module `packages/core/src/live/` (no Node imports) exposes `reduceLive`/`foldLive` over `SummonEvent`s plus a `live.hello` message, exported on the subpath `@poltergeist/core/live` so a browser bundle never pulls Playwright. The CLI's event server (`packages/cli/src/seance-server.ts`) sends `hello` first, replays the non-frame backlog plus each active ghost's latest frame to late joiners, and drops frames (never other events) for a slow client. `run.started` gains `runDir` so evidence frames resolve to `frames/<ghostId>/<seq>.jpg`.

**Tech Stack:** TypeScript (ESM, Node ≥ 22), vitest, ws 8.22.0.

**Spec:** grill rulings for F12 (recorded as D-40 in Task 4), `.kiro/specs/poltergeist/requirements.md` Requirement 11, `design.md` §8, PRD F12, D-39.

## Global Constraints

- No React app, no port 6661: Reanimator renders (D-39). The Séance UI stays deprioritised.
- `packages/core/src/live/` imports nothing from Node or Playwright; only types from other core modules.
- Protocol version constant `LIVE_PROTOCOL = 1`.
- The event server stays loopback-only with the existing origin check and `maxPayload: 1024`.
- Frame backpressure threshold: `bufferedAmount > 1_048_576` bytes → skip that client's `ghost.frame`; non-frame events are never skipped.
- Frame paths: `frames/<ghostId>/<seq padded to 5 digits>.jpg`, relative to `runDir` (matches `createEventSink`).
- `npm run health` green; invisible characters as `\uXXXX` escapes only.

## Review Focus

- Unknown event `type` (a newer engine) → the reducer returns the state unchanged, never throws. (Task 1 test.)
- `verdict.criterion` for an id not in `run.started.criteria` (an `--only` rerun, a reducer started mid-stream) → a line is added, not dropped. (Task 1 test.)
- `ghost.frame` / `ghost.step` for an unknown ghost → ignored. (Task 1 test.)
- A late joiner after `rep.finished` gets no stale frames for ghosts of a finished rep. (Task 3 test.)
- A slow client still receives `run.finished` even while its frames are dropped. (Task 3 test.)
