# F07 Verdicts & Flake Filter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** turn F05's per-pair compile statuses and F06's raw per-rep results into reproducible pair and criterion verdicts (Requirement 7), and fold in KI-37's timeout and attribution fixes so the raw results F07 reads are stable.

**Architecture:** a pure module `packages/core/src/verdicts/`: `pair.ts` decides one pair from its rep results, `compute.ts` joins compile statuses with run results, rolls up per criterion and counts. No I/O, no events (F09 writes `verdicts.json` and emits `verdict.*`). Separately, `runner/run.ts` and `runner/actor.ts` get a per-pair abort on plan timeout, upgrade-only guard attribution, and a better rep error.

**Tech Stack:** TypeScript (ESM, Node ≥ 22), vitest, fast-check, playwright-core (runner tests only).

**Spec:** `.kiro/specs/poltergeist/requirements.md` Requirement 7; `docs/DECISIONS.md` D-06, D-33, **D-34** (the rulings this plan implements); `docs/KNOWN_ISSUES.md` KI-37.

## Global Constraints

- Pure function, fully table-tested (PRD F07). No `fs`, no clock, no randomness in `verdicts/`.
- Threshold = ⌈2N/3⌉ with N = `run.reps` (D-34).
- Precedence `haunted` > `flaky` > `inconclusive` > `clean`, ignoring `notApplicable` (Req 7.4); `uncompilable` rolls up as `inconclusive` (D-34).
- Plan errors and system errors are never app bugs (D-06).
- Reasons are plain QA wording; no theme words (D-09 spirit; F08 owns wording).
- Escapes: invisible characters as `\uXXXX` in source (AGENTS).
- `npm run health` green after every task.

## Review Focus

1. A run that aborted early (fewer results than `reps × pairs`): missing reps must count as not-completed, never as clean. → Task 2 test "missing reps are inconclusive, not clean".
2. A forbidden rule causing an app assertion failure in every rep must not be `haunted`. → Task 1 test "forbidden block voids the rep".
3. Different assertions failing in different reps must not add up to `haunted`. → Task 1 test "different assertions don't add up".
4. Duplicate results for the same pair × rep (a caller bug) must not double-count. → Task 2 test "duplicate rep results throw".
5. Late guard reports after a plan timeout mutating `steps` after return. → Task 3 test "steps are a snapshot after a plan timeout".

**Interfaces:**
- Consumes: `PairRepResult`, `RepOutcome` from `../runner/types.js`; `PersonaId` from `../personas/registry.js`.
- Produces (in `types.ts`):

```ts
export type PairVerdict = 'haunted' | 'flaky' | 'inconclusive' | 'clean' | 'notApplicable' | 'uncompilable';
export type CriterionVerdict = Exclude<PairVerdict, 'uncompilable'>;
export type AssertionTally = { index: number; type: string; failures: number; lastDetail: string };
export type PairVerdictRecord = {
  criterion: string;
  persona: PersonaId;
  verdict: PairVerdict;
  reason: string;
  reps: number;
  threshold: number;
  /** Per assertion index that failed with failure 'app' in a counted rep, ascending index. */
  assertions: AssertionTally[];
  /** Lowest index with the highest failure count; absent when nothing counted. */
  failingAssertion?: AssertionTally;
  /** Reps (1-based, ascending) with at least one counted app failure. */
  failedReps: number[];
  /** Rep outcomes, plus 'voided' (completed but forbidden-blocked) and 'missing' (no result). */
  outcomes: Record<RepOutcome | 'voided' | 'missing', number>;
  /** Artifacts of failedReps, in rep order. */
  evidence: string[];
  notes: string[];
};
export const threshold = (n: number): number => Math.ceil((2 * n) / 3);
```

- Produces (in `pair.ts`): `decidePair(criterion: string, persona: PersonaId, reps: number, results: readonly PairRepResult[]): PairVerdictRecord` — `results` are this pair's reps, any order, ≤ one per rep (Task 2 guarantees it).

Rules (D-34), applied per rep `k` in 1…reps:
- no result → `missing`.
- outcome ≠ `completed` → that outcome; contributes nothing.
- completed with any `blocked` entry of reason `forbidden` or any step `blocked-by-rule` → `voided`; contributes nothing; note `rep k: a forbidden rule blocked a request; its assertions don't count`.
- completed otherwise → `completed`; each assertion with `ok: false && failure === 'app'` counts once for its index (lastDetail = detail from the highest such rep). A rep is "clean" when every assertion has `ok: true`.
- Verdict: max tally ≥ threshold → `haunted`; else any tally → `flaky`; else clean reps ≥ threshold → `clean`; else `inconclusive`.
- `notes` also collects each result's `notes` and `error` as `rep k: …`, in rep order.

Reasons (exact copy, `T` = threshold, `N` = reps, `c` = `outcomes.completed`, `clean` = clean reps):
- haunted: `assertion ${i} (${type}) failed in ${f} of ${N} reps: ${lastDetail}`
- flaky: `assertion ${i} (${type}) failed in ${f} of ${N} reps (needs ${T} to reproduce); ${c} of ${N} reps completed`
- clean: `all assertions passed in ${clean} of ${N} reps`
- inconclusive: `only ${clean} of ${N} reps completed cleanly (needs ${T}); ` + a summary of non-zero non-completed outcomes in the order `planError, systemError, timeout, voided, missing` as `${n} ${name}` joined by `, `.

- [ ] **Step 1: Write the failing tests** — `pair.test.ts` with a builder `rep(k, over: Partial<PairRepResult>)` (defaults: completed, one passing `textVisible` assertion at index 0, no steps/blocked/artifacts). Table cases, N = 3 (threshold 2) unless stated:
  - `threshold(1..6)` → `[1, 2, 2, 3, 4, 4]`.
  - same assertion app-fails in reps 1, 2 → `haunted`, `failedReps [1,2]`, `failingAssertion.index 0`, reason starts `assertion 0 (textVisible) failed in 2 of 3 reps:`.
  - app-fails in 1 rep, 2 clean → `flaky`.
  - app-fails in 1 rep, 2 `systemError` → `flaky`, reason ends `1 of 3 reps completed`.
  - **different assertions don't add up**: index 0 fails rep 1, index 1 fails rep 2, rep 3 clean → `flaky`, tallies `[{0,1},{1,1}]`.
  - 3 clean → `clean`, reason `all assertions passed in 3 of 3 reps`.
  - 2 clean + 1 `planError` → `clean`; 1 clean + 2 `timeout` → `inconclusive`, reason `only 1 of 3 reps completed cleanly (needs 2); 2 timeout`.
  - assertion `failure: 'plan'` in all reps → `inconclusive`; `failure: 'blocked'` → `inconclusive`; `ok: false` with no `failure` → `inconclusive`.
  - **forbidden block voids the rep**: app-fail + `blocked: [{reason:'forbidden', …}]` in all 3 → `inconclusive`, `outcomes.voided 3`; same with a `blocked-by-rule` step instead → `inconclusive`.
  - `host`/`redirect` blocked entries don't void: app-fails in 2 reps with a `host` block → `haunted`.
  - 2 app-fails + 1 `systemError` → `haunted`.
  - N = 1: one app-fail → `haunted`; one clean → `clean`.
  - zero results at N = 3 → `inconclusive`, `outcomes.missing 3`.
  - evidence: artifacts only from failed reps, in rep order; notes prefixed `rep k: `.
  - completed rep with zero assertions counts as clean.

### Task 2: computeVerdicts, rollup and properties

**Files:**
- Create: `packages/core/src/verdicts/compute.ts`
- Create: `packages/core/src/verdicts/index.ts`
- Modify: `packages/core/src/index.ts` (add `export * from './verdicts/index.js';`)
- Test: `packages/core/test/verdicts/compute.test.ts`, `packages/core/test/verdicts/properties.test.ts`

**Interfaces:**
- Consumes: `decidePair`, the Task 1 types; `PairResult` from `../compiler/compile.js`; `RunResult` from `../runner/types.js`.
- Produces:

```ts
export type CriterionVerdictRecord = { criterion: string; verdict: CriterionVerdict; personas: Partial<Record<PersonaId, PairVerdict>> };
export type Verdicts = {
  reps: number;
  threshold: number;
  pairs: PairVerdictRecord[];        // input order of `pairs`
  criteria: CriterionVerdictRecord[]; // first-seen criterion order
  counts: Record<PairVerdict, number>; // over pairs
};
export function computeVerdicts(pairs: readonly PairResult[], run: Pick<RunResult, 'reps' | 'results'>): Verdicts;
export function rollUp(verdicts: readonly PairVerdict[]): CriterionVerdict;
```

`index.ts` exports `computeVerdicts`, `rollUp`, `decidePair`, `threshold` and all types. Note `design.md` §4 already declares `PairVerdict`; this becomes its implementation.

Behaviour:
- `compiled` → `decidePair` with that pair's results (`reps = run.reps`). `notApplicable` → verdict `notApplicable`, `reason` = compile reason. `uncompilable` → verdict `uncompilable`, `reason` = compile reason, `notes` = compile `errors`. Non-compiled records: `assertions: []`, `failedReps: []`, `evidence: []`, `outcomes` all zero.
- Throws `TypeError` when: a run result's `criterion`+`persona` isn't a `compiled` pair (`run result for 3.1/wraith has no compiled plan`); two results share criterion+persona+rep (`duplicate result for 3.1/wraith rep 2`); a result's `rep` is outside 1…reps; two input pairs share criterion+persona.
- `rollUp`: drop `notApplicable`; map `uncompilable` → `inconclusive`; empty → `notApplicable`; else the highest by precedence.
